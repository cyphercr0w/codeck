## Executive Summary

Codeck is a **well-architected** Docker sandbox with strong security defaults. The codebase demonstrates mature patterns: atomic writes, scrypt password hashing, capability-dropped containers, ANSI injection protection, PTY flow control with backpressure, and multi-client terminal support.

**Key strengths:**
- Security-first design (Helmet, rate limiting, lockout, secret sanitization, CSRF defense)
- Clean monorepo structure with independent builds
- Robust PTY lifecycle management with flow control
- File-based memory system with FTS5 search
- Two deployment modes (isolated / managed) with proper isolation

**Key gaps:**
- Test coverage at ~27% backend, 0% frontend (target: 80%)
- 12 routes and 20+ services completely untested
- Several medium-severity security issues need attention
- CSS at 5,070 lines in a single file (maintainability concern)
- Some components exceed recommended 800-line limit

## Security Findings

### CRITICAL (5)

| ID | File | Line | Issue | Impact |
|----|------|------|-------|--------|
| SEC-01 | `cli/commands/init.ts` | 35-40 | Shell injection via `execSync` with interpolated `volumeName` from user-controlled `projectPath` | RCE — arbitrary code execution during `codeck init` |
| SEC-02 | `runtime/services/auth-anthropic.ts` | 98 | `execSync` with string interpolation for agent binary version check | RCE if ACTIVE_AGENT is contaminated |
| SEC-03 | `runtime/routes/workspace.routes.ts` | 56-59 | `tar --dereference` follows symlinks — sensitive files (auth.json) could leak via symlink | Data exfiltration via crafted symlinks |
| SEC-04 | `runtime/services/memory-indexer.ts` | 90-94 | SQL template literal with `${dim}` in `CREATE VIRTUAL TABLE` | SQL injection if embedding dimension is attacker-controlled |
| SEC-05 | `cli/commands/start.ts` | 134-144 | `opts.env` merged into process.env without whitelist | Env var injection — attacker overrides security-sensitive vars |

### HIGH (12)

| ID | File | Line | Issue |
|----|------|------|-------|
| SEC-06 | `runtime/web/websocket.ts` | 200-300 | No session ownership verification — any auth'd user can attach to any PTY session by UUID |
| SEC-07 | `runtime/routes/console.routes.ts` | 33 | `cwd` passed to `createConsoleSession` without path validation |
| SEC-08 | `runtime/routes/files.routes.ts` | 80-84 | `safePath()` uses `resolve()` + `startsWith()` without `realpath()` — symlinks bypass path check |
| SEC-09 | `daemon/services/ws-proxy.ts` | 63-70 | WS pong detection checks for unmasked 0x8a byte, but client frames are always masked per RFC 6455 — pong never detected, all connections timeout |

| SEC-12 | `daemon/services/proxy.ts` | 57-65 | Redirect loop detection too narrow — only checks `host.docker.internal`, misses `127.0.0.1` |
| SEC-13 | `daemon/server.ts` | 97-107 | Password validation only checks length (8-256), no complexity requirements |
